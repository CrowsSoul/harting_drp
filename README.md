# HARTING 设计检查平台——界面架构小组交付说明

本项目是界面架构小组在既有 HARTING 设计检查平台上完成的桌面平台与集成成果，包括工业软件风格界面、分类检查工作台、本地多用户登录、NX 软件衔接、DeepSeek 语义任务，以及统一结果展示与报告。

**小组成员：赵文哲、陈卉妍、杜滨芳。** 本说明按照《第二版规划与分组》中界面架构小组的整体职责编写，不按个人工作拆分。其他小组的规则与检查组件在平台中集成使用，成果来源单独说明。

## 启动与运行环境

本地唯一桌面程序为 `release/HartingDRP_NX.exe`，配套说明、PRT 样例与工程描述格式示例也在 `release`。

1. 将完整发布包解压到本地，运行 EXE，首次使用注册本机账户，之后登录。
2. Windows x64 需要 Microsoft Edge WebView2 Runtime。运行发布包不需要安装 Python 或 Node.js。
3. 没有 NX 的电脑仍可打开平台并使用 JSON 示例检查；实际 NX 建模、改参、插件及原生求解需要本机 Siemens 软件和相应许可证。
4. 进入 **NX 模型与参数**，配置 NX 安装根目录并执行 **检测 NXOpen**；原生电热演示还需要完整 Nastran。Siemens 安装程序、SDK 和许可证不随项目分发。

Git 源码分支忽略 `release/`；仅克隆源码时需按 [开发与构建说明](docs/DEVELOPMENT.md) 构建，或获取后续发布的桌面附件。目前尚未上传 GitHub Release。

## 怎么检查小组实现的功能

### 界面、分类检查、规则与报告

登录平台，在 **检查工作台** 选择专业分类、示例模型、规则版本及检查项，运行检查。查看结果树和三维定位，核对实测值、阈值、严重程度、建议与出处。

进入 **规则配置** 另存一个规则版本，再运行检查；旧任务保留原规则与结果。进入 **任务与报告** 下载 HTML、PDF、Word 或结果 JSON，查看同一任务的输出。切换本机账户时，各自的模型和任务分别保存。

三维视图用于辅助检查。两点距离会标明显示网格近似或包围盒示意，爆炸视图下禁用测量；该读数不能代替工程尺寸验收。

### 语义指令与自动评测

进入 **语义指令**，可先使用离线模式输入 `board_a 跑一遍全部检查`，解析为任务单后确认，或使用一键自动。执行完成后进入主检查工作台查看模型、结果、评语与报告；任务单不完整时需先补齐数据。

需要在线 AI 时，由使用者填写自己的 DeepSeek API Key、模型及 Base URL。界面保存的密钥按本机 Windows 用户加密，接口仅显示掩码。保存并测试可能调用在线服务，项目不提供共享密钥。

上传 `terminal.prt` 后，可使用 `把 terminal 的参数 length 改成 35，再检查 DFM-31` 演示“语义任务 → 实际 NX 改参 → 几何回读 → 统一检查与报告”。

语义场景中的温升／插拔力性能模型与 Siemens 原生有限元是不同的计算路线。下面的 SOL 153 演示通过专用仿真入口运行，不据此宣称任意自然语言都能自动建立并求解任意 CAE 工程。接口与场景见 [语义指令说明](docs/ASSISTANT.md)。

### NX 调起、自动改参与原生插件

在 **NX 模型与参数** 中先取消“完成后自动打开 NX 结果窗口”，创建演示块体，应读到 `length=20`、`width=15`、`height=10` mm。将 length 改为 35，应用并另存，核对参数和实际几何长度均为 35 mm，再点击在 NX 打开本次模型；旧任务仍应为 20 mm。

从平台启动的 NX 2606 中可通过 **菜单 → HARTING** 使用表达式编辑、另存副本、模型与截图导出。回平台选择对应任务，点击 **读取 NX 插件回传**，平台再次调用 NX 独立回读。手动修改需主动导出和读取才同步；其他 NX 主版本需重新编译并实测插件。

### Siemens 原生电热仿真

进入 **NX／Simcenter 仿真 → Siemens Nastran 原生电热衔接演示**，先运行默认 20 A，再将电流改为 40 A 执行。

实际链路为：平台设置参数 → NXOpen 创建真实圆柱 PRT 并回读参数与几何 → 根据回读几何生成固定网格 → Siemens Nastran SOL 153 求解 → 读取实际 F06 温度并检查 OP2 → 与解析解核对 → NX 打开本次模型。

| 核对项 | 20 A | 40 A |
| --- | --- | --- |
| NX 实际长度／截面 | 100 mm／4 mm² | 100 mm／4 mm² |
| 两端温度 | 25°C | 25°C |
| 实际最高温度 | 约 26.34688°C | 约 30.38750°C |
| 焦耳热功率 | 约 0.1724 W | 约 0.6896 W |

每次任务保存独立模型、参数和结果，温升约随电流平方变化。可下载 PRT、DAT、F06、OP2 与结果 JSON，并查看日志或取消运行中的任务。演示采用一维均匀导体、常物性、两端恒温，3 节点／2 个 CROD 单元；未包含接触热阻、对流、辐射、复杂装配或电磁场有限元，不能据此判断任意连接器是否合格。

NX 衔接现场演示见 [演示脚本](docs/DEMO.md)，实测输出见 [原生电热验收](docs/verification/current/原生电热演示验收.md)。

## 与其他小组的协作边界

界面架构小组负责平台界面、账户与桌面封装、NX 衔接、大模型与语义任务，以及各模块在平台中的集成和统一展示。电气安规检查规则的复现归电气安规检查小组；DFM／PERF 组件的公式算法及工程工况建模归相应组件检查小组。平台中出现这些检查项，不表示全部规则由界面架构小组独立开发。

本版已整合第三组 38 条 DFM 公式、受限表达式引擎和所需检查器，来源固定于 [`b57da53bb7a6e4ceba36b0f3b7c7a574d41e9ea4`](https://github.com/CrowsSoul/harting_drp/tree/b57da53bb7a6e4ceba36b0f3b7c7a574d41e9ea4)，保留其贡献记录。公式接入不代表与 Siemens CheckMate 的所有边界逐项等价，也不代表 PERF 工程求解全部完成。详细来源见 [成果来源与分工](docs/INTEGRATION.md)。

本地整理尚未创建 Git 分支、提交或推送。按分组文档，代码发布由各组测试后推进，推送问题由于大淇统一协调；本项目的后续接入步骤见 [分支准备说明](docs/BRANCH_PREPARATION.md)。

## 验证情况与后续验收

现有交付版及目录整理后复验为 **525 个后端测试通过、2 个跳过、200 个子测试通过；14 个前端测试通过**，类型检查、前端构建及 EXE 重定位启动通过。真实 NX／Siemens 演示在 Windows x64、NX 2606 和完整求解环境中完成，旧的 DLL 加载错误 `0xC0000135` 已修复。本轮未调用付费在线模型，不能将离线测试当作在线 API 验收。

限定电热演示的衔接已验收。以下事项仍需按具体场景或项目要求继续验证：完整 SIM/FEM 工程导入后的求解及结果适配、实际产品工况、其他 NX 主版本、另一台无 NX 电脑的完整回归、首屏小于 2 秒、完整 30 分钟人工上手验收，以及发布／CI。历史交接中的旧故障和旧测试数量不代表当前版本状态。

验证索引见 [验收记录](docs/verification/README.md)，目录整理及构建工具检查见 [仓库整理复验](docs/verification/current/仓库整理复验.md)。

## 数据与常见问题

账户、任务、上传模型和规则版本默认保存在 `%LOCALAPPDATA%\HartingDRP`，程序更新或本次源码整理不删除个人数据。在线密钥由使用者自行配置，无密钥时可使用离线语义解析。

白屏或启动失败时，先确认完整解压到本地、WebView2 Runtime 可用，再查看数据目录中的 `desktop.log`。新版已包含 JavaScript MIME 修复；未安装 NX 本身不会导致平台白屏。NX 或求解失败应查看对应任务日志，并核对安装与许可证。
