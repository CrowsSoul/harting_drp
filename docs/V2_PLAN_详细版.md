# 第二版规划与分组（V2）

> 依据：V1 合并版已实测——44 / 44 检查项、312 项单测通过、平台 上传→检查→报告 出 PDF 端到端跑通。
> V2 不是"再加几个检查项"，而是把三件事做成产品能力：**像工业软件**、**规则可对标**、**能听懂人话**。
> 组长除界面组（赵文哲，你已指定）外均为建议，可按实际投入调整。

## 零、一句话

V1 证明了"能查、能出报告"；V2 要证明"专业工具敢用"——界面和 NX 长在一起，规则拿得出出处、对得上行业基准，工程师一句话就能下达仿真评测。

## 一、V2 改什么

| 维度 | V1 现状 | V2 目标 |
|---|---|---|
| 界面 | Vue 单页 + three.js 包围盒示意 | 工业软件风（深色、停靠面板、视口工具条、结果树），与 NX 双向联动 |
| 规则 | `rules/dfm_default.json`：阈值参数 + 严重度 | 公式/表达式 + 比较算子 + 单位/舍入/边界 + 出处（标准条款或工具判定） |
| 安规 | 自研 SAF-01~04 + IEC 60664-1 限值表 | 与 AutoCrear 判定口径对齐，规则来源可审计、可复现 |
| 交互 | 人选模型、点按钮、看结果 | 语义指令 → 结构化任务单 → 自动跑仿真 → 回读结论（人工确认后执行） |
| 交付 | 双击 `启动平台.cmd` 本机跑 | 版本化发布（GitHub Release）+ 可复现环境 + 组内门禁 |

## 二、三条主线

### 主线 A｜平台可视化 + NX 一体化 + 语义指令
**负责：界面架构小组（组长 赵文哲）**

**目标**：让工程师觉得"这是在 NX 旁边干活的专业工具"，而不是一个网页表单。

**范围**

1. **可视化**
   - 工业软件布局：左侧模型/任务树、中间 3D 视口、右侧属性与规则、下侧结果表；
   - 深色主题、视口工具条（剖切、测量、定位、爆炸）、缺陷列表与 3D 联动、爬电路径与包围盒高亮；
   - 界面与报告共用同一套数据（`Finding.location`、`evidence.face_ids`、`path_points`），杜绝"报告和界面对不上"。
2. **NX 衔接**
   - 先分清两种"调用 NX 界面"：
     - **能做**：在平台上点一下，NX 窗口自动打开模型、写好参数、跑检查或仿真——用 NX Open 插件（Block UI Styler 菜单/对话框）+ Journal 实现；
     - **做不到**：把 NX 的视口像 OLE 控件那样嵌进网页（宿主 Python 也不能 `import NXOpen`，见 `docs/NX_ADAPTER.md`）。网页侧继续用 three.js 看轻量化模型，重活留在 NX。
   - 因此做**双向联动**：平台 → NX 下发 JSON 参数，写回 part 表达式与特征参数并触发执行；NX → 平台回传测量值、判定结果、截图，落成任务与报告；
   - 批处理路径保留现有 `run_journal` + 缓存（启动 28.9 s、NX 内部实际 1.26 s），用于批量回归与夜间跑；交互式演示走常驻 NX 会话 + 插件，不稳定的场景退回批处理，保证"能演示、不炸"。
3. **语义指令（DeepSeek）**
   - 链路：自然语言 → DeepSeek（function calling / JSON 输出）→ `TaskSpec`（模型、规则版本、参数覆盖、检查范围、仿真工况）→ schema 校验 → **人工确认** → 执行 → 结果摘要与依据；
   - 每条指令落成结构化记录，可回放、可比对；不允许"模型说什么就改什么"；
   - 密钥走环境变量 `DEEPSEEK_API_KEY`，不入库、不进日志；外网不通时的降级路径见风险表；
   - 失败降级：解析不成就回落到表单，不让用户卡住。

**交付物**：工业风界面 v1（可演示）、NX 插件（菜单 + 参数回写 + 结果回传）、`TaskSpec` 契约与校验器、语义指令服务 + 20 条场景用例。

**验收**：首屏 < 2 s；"改参数 → 仿真 → 回读"闭环 ≤ 3 min；20 条典型指令解析正确率 ≥ 90% 且失败可降级；界面与报告数字一致；工程师 30 分钟能上手。

### 主线 B｜电气安规规则对标
**负责：电气安规小组（组长 宋馨雨）**

**目标**：SAF-01~04 从"我们按标准理解的限值表"升级为"能与 AutoCrear 对齐、每条说得出出处"的规则集。

**范围**

- 判定口径对齐：间隙/爬电的起止点定义、开槽与筋的折算、污染等级、材料组别、海拔与过电压类别修正；
- 规则取证（三步，逐级深入）：
  1. **文档取证**：IEC 60664-1 条款 + AutoCrear 帮助与报告字段，把来源、公式、单位写进 `rules/saf_*.json`；
  2. **黑盒差分**：设计参数化试验件（电压、间隙、爬电、开槽、筋），批量跑 AutoCrear，导出测量与判定，用现成的 `autocrear_compare.py`（逐点误差 + 判定一致）拟合限值面；
  3. **受控静态分析**：只在 1、2 覆盖不到时进行，仅限已购授权、仅用于互操作，且先过合规确认（见第六节）。
- 差异管理：我们更严/更松的项逐条写原因，不允许"为了对齐而放宽"。

**交付物**：`rules/saf_autocrear_v1.json`（规则 + 公式 + 出处 + 置信度）、≥ 20 个试验件的对照报告、差异清单。

**验收**：与 AutoCrear 判定一致率 ≥ 95%，距离误差 ≤ 0.05 mm 或 ≤ 2%；不一致项全部有解释；SAF-01~04 在 mock 与真实 NX 模型上结果稳定。

### 主线 C｜DFM 规则公式化（对齐 Check-Mate）
**负责：DFM 组件小组（组长 张百瑞）**

**目标**：38 项 DFM 从"参数阈值判定"升级为"公式 + 比较规则"，与 NX Check-Mate 的判定口径对齐。

**范围**

- **规则模型 v2**：`RuleBook` 增加 `expression`（受限 DSL，如 `hole_diameter / thickness >= min_hole_diameter_ratio`）、`unit`、`rounding`、`exceptions`、`reference`；`params` 保留做兼容，老规则照常跑；
- **表达式引擎**：解析 → 类型/单位检查 → 求值 → 明确的失败语义（缺数据跳过，不猜结果）；
- **Check-Mate 取证**：
  1. 官方帮助/文档里的 check 定义与参数；
  2. 参数化试验件批量跑 Check-Mate，记录"输入几何 - 参数 - 判定"，形成样本集；
  3. 用样本集核对/拟合我们的公式与常数，逐条落库，标置信度；
- **迁移顺序**：机加 DFM-27~38 → 注塑 DFM-08~18 → 钣金 DFM-19~26 → 装配 DFM-01~07（由 装配 原负责人提供口径）；
- **回归**：13 个 mock 模型 + 试验件双跑，新旧判定差异逐条列账，确认为"修正"而非"漂移"。

**交付物**：表达式引擎、38 条带公式与出处的规则、Check-Mate 对照样本集与报告、迁移差异清单。

**验收**：38 项每条都有公式与出处；与 Check-Mate 在试验件上一致率 ≥ 95%；边界值、单位、舍入有单测；`gen_rules.py` 改为单一真源生成，不再覆盖人工调参。

## 四、发布与工程化（于大淇）

GitHub 推送的问题不靠"多推几次"解决，先把流程定死：

1. **仓库**：单仓多目录（现状）；`main` 只放可发布版本，日常在 `dev` 集成，功能走 `feat/组名-主题` 分支；
2. **提交门禁**：`python -m unittest discover -s tests` 全绿 + 规则库 diff 有说明 + 报告样张；本地 `pre-push` 钩子跑同一套；
3. **不入库**：`.venv/`（120 MB）、`.python/`（42 MB）、`runtime/`、`report_archives/`、`.cache/`；
4. **换行与中文名**：`.gitattributes` 固定 `*.cmd text eol=crlf`、`*.py eol=lf`；`core.quotepath=false`；
5. **凭据**：SSH key 或 PAT，别把 token 写进 remote URL；推送 403 先查权限/2FA，大文件先查 `.gitignore`；
6. **发布**：每周五合并窗口，`v2.0.0-rc.N` 打 tag，Release 附件放整包 zip（运行时另附，不进仓库）。

## 六、风险与合规

| 风险 | 影响 | 应对 |
|---|---|---|
| AutoCrear 无可用授权 | 主线 B 无法对照 | 先用甲方现场机器做导出对照；同时保留自研结果与文档依据 |
| Check-Mate 需额外许可 | 主线 C 取证受限 | 先确认许可；不足时以官方文档 + 客户提供的判定样本补齐，规则里标置信度 |
| 反编译的合规风险 | 交付法律风险 | 优先文档 + 黑盒差分；确需静态分析时，仅限已购授权、仅用于互操作、不复制代码/资源/数据，并由甲方与法务书面确认 |
| 外网受限 | DeepSeek API 不可达 | W1 先验通；备离线降级（本地模型或模板解析），演示不依赖外网 |
| 规则变更导致历史结果变化 | 甲方质疑 | 规则版本 + 双跑对比 + 变更说明；历史任务保留快照（V1 已支持） |
| NX 启动 28.9 s | 交互体验差 | 交互走常驻会话/插件，批处理走缓存 |

**合规边界（写进组内约定）**：我们提取的是"判定口径"——公式、限值、比较算子、边界与舍入，不是复制对方的代码、资源或数据文件；涉及静态分析的动作，先过合规确认再动手。
